五、日记功能
==================================================

5.1 日记年份页面

进入“日记”后显示当前年份十二个月的列表。

每个月显示：

- 月份名称
- 当月日记数量
- 最近一篇日记日期
- 没有数据时显示“暂无日记”

点击月份进入对应月份的日记列表。

5.2 月度日记列表

进入某个月后，显示该月的所有日记。

新用户进入时列表为空，显示空状态：

“这个月还没有日记，点击下方按钮记录第一篇日记。”

页面要求：

- 日记按照日期和时间倒序排列
- 每新增一篇日记，增加一条记录
- 每条记录显示日期
- 显示时间
- 显示正文摘要
- 显示照片数量
- 有照片时可以显示第一张照片缩略图
- 点击记录进入查看或编辑页面
- 支持删除日记
- 删除前弹出确认对话框
- 右下角使用 FloatingActionButton 新增日记
- 修改日记日期后，日记自动归入新的年份和月份

5.3 写日记页面

新增和编辑共用同一个页面。

包含：

- 日记日期
- 日记时间
- 日记正文
- 添加照片按钮
- 保存按钮

日期默认今天，时间默认当前时间，用户可以修改。

日记正文：

- 没有字数限制
- 支持多行输入
- 输入区域适合长文本
- 键盘弹出时不能遮挡主要操作按钮
- 退出页面时，如果内容未保存，需要提醒用户
- 可以实现本地草稿自动保存
- 正式保存后清除对应草稿

保存条件：

- 正文和照片至少有一项不为空
- 正文为空但存在照片时允许保存
- 正文和照片都为空时不允许保存，并显示提示

5.4 日记照片

使用 Android Photo Picker，不要申请不必要的整个存储权限。

要求：

- 可以从手机选择一张或多张照片
- 可以多次添加照片
- 已选择照片显示为缩略图
- 不要在列表中直接加载完整原图
- 使用 Coil 加载图片
- 点击缩略图进入全屏图片预览
- 全屏预览显示较高清图片
- 支持双指缩放
- 支持拖动
- 多张照片时支持左右切换
- 支持从当前日记中移除照片
- 移除前可以确认
- 单张图片加载失败时显示错误占位图，不能导致整个页面崩溃

非常重要：

不能只保存 Photo Picker 返回的临时 URI。

保存日记时，将照片复制到 App 自己管理的内部文件目录，例如：

filesDir/diary_images/

数据库只保存由 App 管理的相对路径或可靠路径。

删除日记时，清理该日记不再使用的照片文件。

避免同一个图片文件被误删。

==================================================
八、数据导出和恢复
==================================================

这是核心功能，必须真实可用，不能只制作静态页面。

8.1 数据导出

数据管理页面提供“导出全部数据”。

导出内容：

- 全部日记
- 全部日记照片
- 全部账目
- 全部分类
- 数据格式版本
- App 版本
- 导出时间

导出为一个 ZIP 文件。

文件名示例：

life_record_backup_2026-07-10_153000.zip

ZIP 内部建议结构：

- manifest.json
- diaries.json
- accounts.json
- accounts.csv
- categories.json
- images/

要求：

- JSON 使用 UTF-8
- 账目同时提供 JSON 和 CSV
- CSV 至少包括：
  - 日期
  - 时间
  - 类型
  - 金额
  - 名称
  - 分类
  - 备注
- ZIP 中的图片使用相对路径
- 不允许把当前手机的绝对路径写入备份
- 使用 Storage Access Framework，让用户选择保存位置
- 显示导出中状态
- 导出成功后显示提示
- 导出失败时显示可理解的错误信息
- 所有流和文件句柄必须正确关闭

8.2 导入恢复

提供“从备份恢复”。

要求：

- 使用系统文件选择器选择 ZIP
- 校验 ZIP 文件
- 校验 manifest.json
- 检查备份版本
- 显示备份基本信息：
  - 导出时间
  - 日记数量
  - 账目数量
  - 图片数量

提供两种方式：

1. 合并数据
2. 清空当前数据后完整恢复

完整恢复必须二次确认。

导入需要：

- 使用 Room Transaction
- 失败时回滚数据库
- 根据 UUID 处理重复数据
- 将图片解压到 App 内部图片目录
- 防止 ZIP 路径穿越攻击
- 限制异常或恶意超大文件
- 不能因为一张损坏图片导致全部导入崩溃
- 数据恢复完成后页面立即刷新

对于数据库数据和图片文件无法完全使用同一个事务的问题，需要设计临时目录：

1. 先解压并校验到临时目录
2. 数据全部验证成功
3. 再执行数据库事务
4. 成功后移动图片
5. 失败时清理临时文件并尽量恢复原状态

## 二、先排查启动卡顿

请重点检查以下问题：

* Application、MainActivity、首页初始化阶段是否执行了数据库查询、文件扫描、图片读取、JSON 解析或其他耗时操作。
* 是否在主线程中调用 Room、SQLite、SharedPreferences 大量读写、文件 IO 或图片解码。
* 是否在首页一次性加载全部月份、全部日记、全部账单或全部图片。
* 是否存在重复查询数据库、重复收集 Flow、重复创建 ViewModel、重复执行初始化代码。
* Jetpack Compose 中是否存在不必要的重复重组，例如：

  * 在 Composable 中直接查询数据库。
  * 每次重组重新排序、分组或转换列表。
  * LazyColumn 没有稳定 key。
  * 状态对象不稳定。
  * 图片或日期格式化在每次重组时重复执行。
* XML 项目中是否存在 RecyclerView 一次性加载过多数据、嵌套滚动、布局层级过深或在主线程处理图片的问题。
* 是否有启动时同步读取大量本地图片缩略图的问题。

找到原因后再修改，不要只增加启动页掩盖卡顿。

## 三、页面动画优化

请给以下交互添加轻量、自然且统一的动画：
* 进入首页。
* 首页进入日记、记账、睡眠等其他所有的模块。
* 日记、账单、睡眠等列表进入详情或编辑页面。
* 新增、删除日记、账单、等记录时的列表变化。
* 月份切换或翻页。
* 页面返回上一级。
* 空状态与有数据状态之间的切换。
* 弹窗、底部菜单和新增按钮的出现与消失。

动画要求：

* 页面进入建议使用轻微淡入加水平位移。
* 返回时使用相反方向动画。
* 列表增删使用 placement、fade 或 size 动画。
* 月份切换可以使用横向滑动，但不要出现明显延迟。
* 动画时长控制在约 180～300ms。
* 不要滥用复杂弹簧动画。
* 不要给每个列表项同时运行高开销动画。
* 遵守系统“减少动态效果”或动画缩放设置。
* 快速连续点击时不能重复打开页面。
